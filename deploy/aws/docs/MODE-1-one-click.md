# Mode 1 — One-click CDK deployment

Deploy Open WebUI to AWS directly from your machine. No CI/CD, no Git wiring — just CDK.

## Prerequisites

- AWS account + credentials (an AWS CLI profile, or environment credentials).
- Node.js 20+ and npm.
- AWS CDK is installed on demand via `npx` (no global install required).
- **Docker is only required if you build from source** (`--build`). The default pulls the
  official prebuilt image, so Docker is not needed.
- For a **custom domain**: an ACM certificate **in `us-east-1`** (CloudFront requirement),
  regardless of which region you deploy the app to.

## Fastest path

```bash
cd deploy/aws
./deploy.sh --profile YOUR_AWS_PROFILE
```

This:
1. Validates credentials and resolves your account id.
2. `cdk bootstrap`s the account/region (idempotent).
3. Deploys `OpenWebUI-Network`, `OpenWebUI-Data`, `OpenWebUI-Compute`.
4. Prints the CloudFront app URL.

Open the printed URL. The **first user to sign up becomes the admin** (Open WebUI's
built-in auth, since `auth.mode=none` by default).

## Common options

```bash
# Custom domain (ACM cert must be in us-east-1)
./deploy.sh --profile prod --domain oui.example.com \
  --cert-arn arn:aws:acm:us-east-1:123456789012:certificate/abcd-...

# Pick a region
./deploy.sh --profile prod --region us-west-2

# Use an opt-in config file (Bedrock + Cognito, build from source)
./deploy.sh --profile prod --config cdk/config/example-bedrock-cognito.json

# Add Cognito SSO on top of the defaults
./deploy.sh --profile prod --auth cognito

# Enable Bedrock as a provider (requires Bedrock code in the image — use --build or a fork image)
./deploy.sh --profile prod --bedrock --build

# Non-interactive
./deploy.sh --profile prod --yes
```

After deploy, point your DNS `CNAME` (or Route 53 alias) at the CloudFront domain printed
at the end.

## Driving CDK directly (no script)

```bash
cd deploy/aws/cdk
npm install
ACCOUNT=$(aws sts get-caller-identity --query Account --output text)

# vanilla
npx cdk deploy --all -c account=$ACCOUNT

# with a custom domain
npx cdk deploy --all -c account=$ACCOUNT \
  -c environment=default -c domainName=oui.example.com \
  -c certificateArn=arn:aws:acm:us-east-1:...:certificate/xxxx
```

## Updating

Re-run the same command. For a new Open WebUI version, bump `image.tag` (in your config
file or `-c imageTag=v0.9.7`) and redeploy — CloudFront/ALB stay in place; ECS rolls the
task with circuit-breaker rollback if the new task fails health checks.

## Cognito mode follow-up

When you deploy with `--auth cognito`, the user-pool **client secret** is generated by
Cognito and must be placed in Secrets Manager (`<appname>/cognito-client-secret`) and the
callback URLs confirmed. The pipeline modes do this automatically in a post-deploy step;
for a one-click Cognito deploy, sync it once:

```bash
POOL_ID=$(aws cloudformation describe-stacks --stack-name OpenWebUI-Auth \
  --query "Stacks[0].Outputs[?OutputKey=='UserPoolId'].OutputValue" --output text)
CLIENT_ID=$(aws cloudformation describe-stacks --stack-name OpenWebUI-Auth \
  --query "Stacks[0].Outputs[?OutputKey=='UserPoolClientId'].OutputValue" --output text)
SECRET=$(aws cognito-idp describe-user-pool-client --user-pool-id $POOL_ID \
  --client-id $CLIENT_ID --query "UserPoolClient.ClientSecret" --output text)
aws secretsmanager put-secret-value --secret-id open-webui/cognito-client-secret \
  --secret-string "$SECRET"
```

(For most users the built-in auth — `auth.mode=none` — is simpler and needs none of this.)

## Tear-down

```bash
cd deploy/aws/cdk
npx cdk destroy --all -c account=$ACCOUNT
```

Aurora, the S3 upload bucket, and the Cognito pool use `RETAIN` removal policies, so they
survive a destroy by design — delete them manually if you truly want them gone.
